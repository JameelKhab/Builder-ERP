# Quality / NCR original contract v1

Scope: F013/F149, R-01/R-10/R-11/R-12, M03/M04/M28/M32, with evidence storage supporting future M27. Preserve all other quality, HSE, inspection, snag and controlled-document requirements as open. This contract implements NCRs; it does not relabel every quality/HSE sample as operational.

Evidence: retained source observations 56–59; fresh read-only NCR 43, 29 October 2026, captured in validation/quality. Visible source fields are Name, Kind, Project, WBS, Responsible, Due Date, Severity, Authority Reference, Details/Hazards, Resolution, submitted/resolved/closed times, verifier and attachments. Visible states: Draft, Awaiting Review, In Progress, Resolved, Verified/Closed. No source mutation or enforcement test was performed. Original Builder enhancements below are explicit policy choices, not claims about hidden source rules.

## One case, clear next action

Draft → Open investigation → Plan review → Corrective work → Verification → Closed. Independent reviewer can return the plan or fail verification; closed cases reopen as a new cycle while retaining every earlier fact/file/decision. A draft can be cancelled, with reason, and is never deleted. Reporter and responsible owner prepare the case; assigned action owners complete their own tasks. Assigned reviewer must have live quality.review scope and be independent of reporter, owner, plan author and action completers. Project managers and QA officers can review; assignment does not create authority.

Case: stable ID, company/project, WBS/location, observed date, title, requirement reference, observation, severity, reporter/owner/reviewer, due date, version, current cycle/state, containment, root cause, disposition, remedy, acceptance criteria, authority reference. Optional receipt origin is scope-checked and carries quantities, not pricing. Project/company ownership cannot change. Core description can change only before submission; triage assignment/date changes are audited and cannot bypass independence or pending review freezes.

Containment can be recorded immediately after submission, before root-cause analysis is complete. Plan: current-cycle containment, cause, disposition, acceptance criteria, tasks with explicit owner/due, evidence. Use-as-is requires a named external authority reference and authority evidence; local review does not certify external consent. Submission freezes a plan snapshot in append-only history. Plan revision after return retains history. Corrective work cannot begin in this workflow until independently accepted. All actions must be completed with evidence before submitting for verification. Verification requires a fresh reviewer-authored file for this submitted cycle and a stated result against acceptance criteria. Failure returns one selected action to work, with reason. Closed case reopening clears the current plan and creates a new cycle; previous tasks/evidence remain readable.

Evidence: original bytes, SHA-256, safe filename, media type, size, author/time, case/cycle/purpose and optional action reference. Append-only database blobs, max 2 MiB each, allow PDF/PNG/JPEG/plain UTF-8 text with signature checks, attachment-only download; no remote URL fetching or executable/HTML/SVG rendering. Evidence never silently changes version. Files are included in database recovery comparisons. File attachment is not a full document-control/retention system or malware certification.

Cost/waste/change/delay consequences each require an explicit assessment before verification: not expected with reason, or follow-up with owner/due/reason. Follow-up does not create cost, disposal, entitlement, variation, schedule or cash facts. Quality closure can leave clearly reported downstream follow-ups open; their typed operational resolution remains dependent on those domains. These obligations remain visible after closure.

## Permissions, reports and consistency

Service checks company/project/capability on every read/write/download/report/search; preview is read-only. All mutations require current case version, transactions and append-only case history. Actor changes and revoked assignments are checked live. Company lists/reports include only authorised projects; inaccessible case/file identifiers return unavailable. No prices/medical/personal incident details are introduced in the NCR model.

NCR report: current operational population by company/project/state/severity, generated UTC timestamp, definition/rule version, complete-filter findings, open/overdue/review/closed/reopened-cycle counts and pending consequence follow-ups, source case IDs. Reopened cases count once by current state; cycles are separate history. No claim of historical cutoff/as-of reconstruction. CSV has findings before all matching rows and formula-safe cells.

Examples in every supplied project: one draft, one corrective-work case, one closed-then-reopened case, one awaiting plan review and one awaiting verification, with fictional requirements/files, assigned people, independently reviewed plans, completed actions and verification history. Additive pack cannot overwrite user or existing example data. No real account credentials are configured.

Acceptance: lifecycle/evidence gates; independent review; stale versions; fail/reopen retaining old evidence; scope and file isolation; live revocation; current-cycle evidence and owner checks; consequence completeness; complete population reports/export; additive examples; preservation/recovery; browser desktop/mobile. Source import/full parity, representative-user validation and broader quality/HSE/inspection/ITP/handovers remain open.
