# Procurement contract — original implementation, 29 October 2026

Scope references: D06–D08; F070, F073–075, F081–082, F085, F090, F103, F109–112; M03–M04, M06, M10–M14, M24, M32. Retained read-only source evidence 19 (requested quantities/restricted pricing and released WBS reservation), 21 (order/product/received/billed/currency), 22 (receipt/return/source order), 25 (WBS/company/code/parent/release). These establish fields and intended behaviour, not tested source enforcement.

Builder requirements: multi-line unpriced demand, typed product/UOM/location/WBS, product-specific quotes, explicit transaction currency and dated FX, split sourcing, independent approval, atomic reservation-to-commitment conversion, partial accepted/rejected receipt, return against receipt, controlled stock issue and traceable costs. Unknown source overspend/overreceipt rules use conservative rejection pending parity review. No external PO is sent; order issuance is a local ledger action only.

State contract:
- Request draft → submitted → awaiting approval → approved → ordered. Return from review → submitted; revise draft quantities before resubmission; cancel unapproved work with reason. No quantity mutation after approval.
- Quotes attach to a submitted request line, product and UOM; vendor/company currency, unit price, validity, conversion rate/source/date frozen. Source allocations must total each requested line exactly before review; multiple vendors/currencies become separate linked orders.
- Approval is independent of requester and sourcing-plan author, within explicit company-currency limit and released work-item allowance. Recheck quote validity/FX and available budget when approving. Pending review reserves nothing. Approved allocations reserve once; issued orders replace their own reservation exactly once. No incurred cost or cash is manufactured at this handoff.
- Receive only issued orders. Accepted + rejected quantity in one receipt cannot exceed outstanding quantity. Rejected goods are recorded but not put into stock; replacement remains outstanding. Duplicate idempotency keys cannot repeat a receipt.
- Supplier return references a receipt and cannot exceed its unissued/unreturned accepted stock. It reopens outstanding supply; it is not an automatic vendor credit or payment reversal.
- Issue references a receipt lot, WBS and structured location within the same company/project. No negative stock. Stock value is allocated from the lot's remaining value; the final consumption/return uses the exact remaining value. Material use creates incurred-cost facts, never cash. Each receipt is valued independently using its frozen quote/FX; order-versus-receipt rounding differences remain explicit.

Security: reads and writes use current company/project capabilities; site users can request and receive without seeing prices; procurement sees commercial sourcing but does not inherit budget reporting; receiving/stock actions do not grant approval. Transactions enforce state/revision/reference boundaries. Audit history and stock/cost facts are append-only. Client totals, roles, companies and price/currency overrides are never trusted.

Opening data: legacy local cost_items are retained as explicitly illustrative opening snapshots. New transaction facts add to these snapshots without modifying original budget or pretending to import source accounting. Legacy one-line requests are retained, visible as earlier requests, and excluded from typed-order creation until explicitly migrated; their existing approved reservations are considered in availability.

Acceptance examples: unpriced 100-unit site demand; split 60 EUR / 40 AED quotes; independent review; two local orders; partial receipt with rejection; return available goods; issue remainder to a location; verify outstanding demand, stock/value, commitment, cost, no cash and immutable history. Exercise duplicate commands, stale revisions, self-approval, wrong company/project/product/location, stale FX, budget exhaustion, overreceipt, over-return, over-issue and role-based redaction. Full accounting/bill matching, taxes/freight, agreements, source imports and full parity remain separate open work.
