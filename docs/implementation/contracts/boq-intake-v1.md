## Original workflow

- An estimate's current author uploads one to five XLSX/UTF-8 CSV files into a separate intake. Original bytes, SHA-256, filenames, parsed sheets/cell references and upload identity are retained locally. Upload/check never change the estimate.
- Choose a sheet/header and explicit column mapping per file, with optional company product and cost-code defaults. Recognised headings are suggestions; unknown populated columns, formulas/errors, hidden data, ambiguous headings, invalid units, duplicate codes, unsupported parent caps/shares or unsupported payload are blockers, never silently dropped. Unselected sheets and rows above the header remain visible and retained; the selected scope is explicitly reconciled by the reviewer.
- One row represents a direct-rate BOQ item with quantity **per building**, in the estimate currency. Product reference and cost code must resolve in the estimate company. Product/unit mismatch is blocked; no inferred conversion. Existing resource assemblies and building exceptions stay unchanged. This intake appends new items; it cannot overwrite a previously reviewed line.
- Every file requires an explicit expected direct total, including an explicit zero. The total is the sum of rounded quantity × repeated buildings × direct rate, excluding indirect/markup; different units are never added into one quantity total. Preview shows per-unit quantities, file differences, row-specific errors and the complete resulting estimate totals. Any blocked row/file blocks the entire batch.
- Saved checks, mappings, resolved master snapshots, calculation result and estimate version are immutable. A fresh check replaces the active candidate while retaining earlier checks. Another currently authorised tender reviewer approves a clean check, with an explicit reconciliation confirmation. Intake data review does not grant financial authority or approve the estimate.
- Commit requires the original author, current draft/returned estimate access, unchanged estimate version, current reviewed mappings/masters/calculation, and a still-authorised independent reviewer. One transaction appends every row, records exact line provenance and marks the batch committed. Repeating a successful commit returns the existing result. Duplicate files/BOQ codes cannot create a second append. Approved/submitted estimates cannot be changed. The authorised author can cancel a still-unapplied intake even after the target was submitted, retaining its files and checks without changing the estimate.
- Scoped intake queues, findings, evidence download and history follow the estimate's company/project permissions. Access preview is read-only. Uploads never execute macros/formulas or fetch external links. Bounded ZIP/XML/CSV parsing limits resource use. Original files download as attachments.

## Acceptance checks

Invalid unit retains filename/sheet/row/cell and leaves the estimate unchanged. Mixed good/bad files commit nothing. A formula's cached value never bypasses rejection. Arabic headings and explicit custom mappings resolve correctly. Exact file totals include repeated buildings. A second reviewer is required; stale estimate/master/scope/reviewer changes invalidate review. Retrying commit creates no duplicate line. Approved revisions retain source lineage. Company/project/API/export/preview boundaries, immutable evidence and database recovery must pass.
